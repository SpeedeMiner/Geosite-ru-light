# Почему прежний HTTP 200 не стал правилом

Переанализированы все 45 прежних отложенных имён по сырым данным и тем же ID. Сверены SHA-256 тел, тип, точный target, путь, три ASN и статус. Во всех 42 случаях `hold_content` три ответа имеют `truncated: true`. У 28 из них ни одна точка не успела получить закрытие HTML head. У `dgtl.market` видна лишь ссылка для перехода к содержимому, а не само содержимое. Нет основания считать эти ответы блокировкой или принимать их только по заголовку.

Это ограничение инструмента, а не догадка по длине. Публичная реализация Globalping фиксирует лимит 10000 единиц строки после декомпрессии и возвращает `truncated`. Тот же исходник возвращает причину проверки TLS в `tls.error`. [Код получения тела](https://github.com/jsdelivr/globalping-probe/blob/1f7afe33fab0e96ca8931857411ea62a752ae2ee/src/command/handlers/http/undici.ts#L487-L503), [поля результата](https://github.com/jsdelivr/globalping-probe/blob/1f7afe33fab0e96ca8931857411ea62a752ae2ee/src/command/handlers/http/undici.ts#L617-L635).

`09-archive-diagnostics.jsonl` добавляет проверенные признаки к прежним измерениям, не меняя исходные журналы. Обновлённый исследовательский `probe-wave.py` хранит `body_truncated`, `tls_error`, нормализованный тип ответа и источник ошибки. Порог видимого содержимого и правила TLS/SAN не менялись. Пройдены 17 тестов, в том числе три новых. Никаких сетевых проб этот этап не запускал.
