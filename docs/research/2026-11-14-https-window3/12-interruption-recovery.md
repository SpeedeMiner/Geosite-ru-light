# Возобновление партии после обрыва

Для каждой партии сохранять отдельную директорию вне git. В ней `submitted.jsonl` (точные имя, URL, ID и время отправки), `evidence.jsonl` и сырые ответы. В исследовательскую ветку переносить только компактные данные и SHA-256 тел.

Если процесс прервался, не запускать ту же партию целиком. Сначала сверить предыдущий список с журналом. Офлайн-восстановление не меняет файлы партии.

```sh
python3 recover-wave.py 08-wave-a.tsv /path/to/wave-a > /path/to/recovered-a.jsonl
```

Если сырой ответ по известному ID не сохранился, повторить с `--fetch`. Это только GET по записанному ID, без новых измерений. Результат `submission_unknown` означает, что локальный ID не найден. Он не доказывает, что запрос не ушёл, поэтому повторять вслепую нельзя. `recovery_pending` сохраняет ID для продолжения позже. При наличии временного каталога и сырого ответа новые запросы не нужны. Даже `https_candidate` не утверждает правило автоматически.

Шесть тестов восстановителя прошли, включая оборванную последнюю JSONL-строку и подменённый ID. На реальном архиве `germesplit.com` искусственно удалена компактная запись из копии партии. По записанному ID и сырому ответу офлайн восстановились то же решение транспортного фильтра и все три SHA-256 тел. Существующий оригинальный архив не менялся.
