# Сверка GeoSite v11.18 через GET

Этот аудит не меняет маршрутизацию, PR GeoIP №5, release или теги. Из диагностики PR №5 взяты раздельные наблюдения по ASN, семействам IP и отсутствие автоматической трактовки тайм-аута как блокировки. Сетевой код выполняет только DNS и обычный HTTPS GET к опубликованной странице. ASN 3216, 12389 и 207957 в RU, по одной точке на ASN. Состав точек проверяется по фактическому ответу. Метка сети не считается свидетельством домашнего подключения.

- **inventory.json**, **baseline-exact.tsv** и **suffix-inventory.tsv** — инвентарь из проверенных DAT. Точные правила Light и Server совпадают. Суффиксы исследуются выборкой и не отправляются как цели (например, `ru` никогда не становится URL). Неизвестный путь точного имени обозначен корнем `/`, это тест главной страницы, не всего сервиса.
- **pilot.tsv** — 19 отложенных целей, 31 имя кандидата, 6 точных имён из релиза, пять подстановок для суффиксов и одна контрольная цель. **baseline-batch-001.tsv** — ещё пять точных имён из DAT.
- **dns-dual-stack.tsv** — пять диагностических целей для независимых A/AAAA и IPv6. Запись AAAA не означает успешный IPv6 GET. Семейство GET сверяется с адресом из ответа.
- **archive-reviewed.tsv** — переразбор старых захватов. Это не свежий сетевой прогон. **archive-dispositions.tsv** — промежуточный отчёт до исправления ложного распознавания веб-заглушки. Пользоваться следует `archive-reviewed.tsv`.
- Для свежих результатов исходный редирект и его объявленная цель сохраняются, но не обходятся автоматически. Ни HTTP 200, ни найденный текстовый маркер не являются автоматическим допуском в RU. Обрезанный HTML или бездействующие точки помечаются отдельно. API возвращает текстовую копию ответа, исходные байты Windows-1251 из уже испорченной строки восстановить нельзя.
- Для независимого продолжения --size 50 делит инвентарь на группы до 150 проб IPv4. Перед запуском проверяется квота. При её исчерпании скрипт не посылает пробы, не меняет учётную запись и не использует другой выход. Не запускайте сразу все партии, если квоты не хватает.

```sh
python3 -m unittest -v test_audit.py
python3 audit.py pilot.tsv results-pilot.jsonl --reserve 10
python3 audit.py dns-dual-stack.tsv results-dns.jsonl --test a --test aaaa --test get6
python3 audit.py baseline-batch-001.tsv results-baseline-001.jsonl
python3 batches.py baseline-exact.tsv remaining --exclude pilot.tsv --exclude baseline-batch-001.tsv
```

## Очередь после окна 010

Обе очереди сверены с 237 уже записанными верифицированными GET IPv4.
Файлы планов не являются журналом сетевых запусков.

1. Сначала [план 010](wide-009/next-get-window/summary.json),
   [первая партия 80 URL](wide-009/next-get-window/first.tsv) и
   [вторая партия 14 URL](wide-009/next-get-window/next.tsv).
2. Затем [дополнительный план 011](wide-010/supplement-011/summary.json),
   [первая партия 80 URL](wide-010/supplement-011/first.tsv) и
   [39 отложенных контролей](wide-010/supplement-011/deferred.tsv).
   В первой партии сначала девять непокрытых диагностик,
   затем 48 корней из готового RU с пробелом в архивных данных,
   затем 23 контрольных адреса.
3. Только после восстановления квоты команду из примера ниже можно
   запустить отдельно на первой партии 010. Файл результата должен быть
   новым. Если получено частичное наблюдение, сначала зафиксируйте
   завершённые записи и проверьте, что осталось. Повтор полного списка
   после частичной остановки тратит квоту и создаёт дубли.
   Незавершённые строки не становятся подтверждёнными по наличию ID.
   Если квота восстановилась до 250, партия из 80 URL расходует 240 проб.
   Следующие 14 URL требуют ещё 42 пробы, поэтому не запускайте их
   сразу вслед за первой партией в том же окне.

```sh
python3 -B audit.py wide-009/next-get-window/first.tsv live-window-010-first.jsonl --test get4 --reserve 10
```

За окном 010 остаются [каталоги](wide-010/supplement-011/hosts.tsv),
[матрица цепочек](wide-010/routing-chains.md) и [архивная сводка](wide-010/archive-summary.json).
В архивных GET сохранены отдельно HTTP, факт доверия TLS и число ASN.
Архив не даёт свежего сетевого зачёта и сам по себе не даёт основания для
правила `full:`. Для повтора составления очереди без сети укажите новый
каталог результата командой `python3 -B supplement_011.py /tmp/geosite-011-replay`.

## Очередь после окна 011

[Первая партия 010 завершена](wide-011/first-final/summary.json).
Следующая обычная квота нужна для [80 GET](wide-011/next-quota/first.tsv).
Это 14 оставшихся адресов плана 010 и 66 из дополнительного плана 011.
При 250 пробах в квоте команда по-прежнему оставляет 10. Точку входа для
оставшихся 104 URL см. в [сводке](wide-011/next-quota/summary.json).

```sh
python3 -B audit.py wide-011/next-quota/first.tsv live-window-012-first.jsonl --test get4 --reserve 10
```

Команда `seal_window.py PLAN RESULTS LIGHT_DAT SERVER_DAT NEW_DIR`
отдельно сохраняет верифицированные ответы, уже известные ID без итоговых
ответов и ещё не появившиеся в файле строки. Во время активного прогона
очередь не перезапускается по промежуточному снимку. Фиксируйте единственный
закрытый файл и опрашивайте существующие ID по нему до переотправки.

Резервный `workspace_get.py` не обращается к Globalping. Он выполняет
ограниченные публичные HTTPS GET с фактической сети текущей среды и хранит
их отдельно. Даже при HTTP 200 он не доказывает доступность из России и не
записывается в `live-*.jsonl`. Для независимых результатов из пользовательской
сети нужна точка с подтверждённым egress, которой текущая среда не является.
