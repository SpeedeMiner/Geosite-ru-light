# K2 Cloud и Cloud4Y — окно 16.11.2026

База — номерной v11.21 Light и Server. В каталог входят исследовательские данные и списки для моделирования. Ни один файл отсюда не считывается производственным сборщиком.

## Что проверяли

- [Входы S3](s3-plan.tsv), [API K2](k2-api-plan.tsv), [отдельный публичный PDF и консоль](s3-object-plan.tsv), [официальные веб-адреса](public-web-plan.tsv). Публичный PDF АТОЛ опубликован по прямой ссылке в [базе знаний SIGMA](https://support.sigma.ru/knowledge_base/item/267778). Запрашивались только первые 512 байт, без ключей S3, входа в консоль или обращения к непубличным данным.
- [Покрытие v11.21](coverage-v11.21.tsv) для первых трёх планов, [DNS Google и Cloudflare](dns-workspace.tsv), [BGP origin RIPEstat](ripe-origins.tsv), [HTTPS из рабочей среды](https-workspace.tsv), [отдельный контроль публичного объекта](object-workspace.tsv). DNS-наличие и ASN назначения сами по себе не подтверждают доступность из РФ.
- [Российские измерения S3](vpn-s3.tsv) и [K2 API](vpn-k2-api.tsv) · [Actions 43876937970](https://github.com/SpeedeMiner/Geosite-ru-light/actions/runs/43876937970). [Измерения PDF/консоли](vpn-s3-object.tsv) · [Actions 43877487061, попытка 2](https://github.com/SpeedeMiner/Geosite-ru-light/actions/runs/43877487061/attempts/2). В сводках JSON зафиксированы SHA-256 исходных ZIP. Публичные таблицы не содержат IP VPN-выходов.
- Российские замеры делались по IPv4 через VPNObratno отдельно из AS12389 и AS44347, без Globalping. Они не являются измерением из домашней сети пользователя. Ни одного AAAA в публичном срезе 17 имён не вернулось. [Каталог для локального домашнего HEAD](home-probe-targets.json) проходит штатную валидацию, но не запускался. Его можно передать `--targets` в [закреплённый home_probe.py](https://github.com/SpeedeMiner/Geoip-ru-server/blob/30e797f05ddb8e38ccc2c44938b64846b4fce2fb/.github/reachability/home_probe.py) и выполнить на согласованной российской сети. Этот скрипт не заменяет GET публичного PDF и не отправляет данные автоматически.

## Решение по первой группе

| Результат | Решение |
| --- | --- |
| `s3.k2.cloud`: 206, 512 байт публичного PDF, SHA-256 совпал в обоих ASN и внешней контрольной пробе. | Точное имя в очереди. Подтверждена выдача публичного объекта, не авторизованная S3-операция. |
| `console.k2.cloud`: 200, HTML с заголовком консоли, одинаковые 793 байта. | Точное имя в очереди. Подтверждён входной документ, не вход в аккаунт. |
| Два региональных S3 K2: 307 на инструкцию. Два адреса Cloud4Y: 403 XML, обычная проба декодировала AccessDenied. | Резерв до подтверждения реального чтения или публичной зависимости на каждом имени. |
| Восемь хостов API K2: 400 XML или JSON в двух ASN. | Резерв. Принадлежность и ответ подтверждены, рабочие операции не проверены. |
| `elastic.k2.cloud`: нет пригодного A. Контроль `s3.objstor.cloud4y.ru`: два строгих TLS-отказа. | Не добавлять. Правило .ru уже имеется и не заменяет проверку работоспособности. |

[Предпросмотры Light и Server](preview.tsv). `+1`, `+5`, `+13` — испытанные сценарии сборки, не готовые очереди. `4pda.to`, BLOCK, Hydra и `selcdn.net` остаются без изменений.

## Итог окна

Дополнительный [двухсетевой прогон](https://github.com/SpeedeMiner/Geosite-ru-light/actions/runs/43878405029): [VPN](vpn-public-web.tsv), [контроль рабочей сети](public-web-workspace.tsv), [сверка покрытия](public-web-coverage.tsv). На `site-api.k2.cloud` обе сети получили завершённый `200 image/svg+xml`. SHA-256 первых 10 000 байт совпал с внешним контрольным SVG, на который ссылается сама главная K2. [Подтверждение](public-site-asset-proof.tsv).

Итоговая исследовательская очередь — [три точных имени](plus3/scope.txt), без релиза. Light 4 622, Server 4 510, ни одного удаления или нового суффикса. Остальные `+N` в [матрице](preview.tsv) — альтернативные сценарии, не очереди. У `docs.k2.cloud`, `k2.cloud`, `promo.k2.cloud` и `team.k2.cloud` AS44347 показал `200` и узнаваемый заголовок, но передача не завершилась (`curl=28`). Повторить эти четыре короткими публичными путями или с другим независимым RU ASN. Региональные S3 и Cloud4Y требуют опубликованных объектов на соответствующих точных хостах. [Контроль указателей публикации](publication-guard.tsv).
