# Отдельный GeoSite-пилот через VPNObratno

VPN-транспорт взят из GeoIP PR №5, коммит
`30e797f05ddb8e38ccc2c44938b64846b4fce2fb`. PR и его рабочая ветка
не меняются. Три используемых файла проверяются по SHA-256 перед импортом
адаптера. Тот же VPN-транспорт уже установил выход AS6856 в
[GeoIP Run #24](https://github.com/SpeedeMiner/Geoip-ru-server/actions/runs/43093976146)
с 28 из 30 проверок HEAD. Это не результаты нового GET-пилота.

Адаптер сохраняет механизм скачивания и проверки профилей, OpenVPN,
netns, kill-switch и проверку страны/ASN. Он фильтрует VPN-выходы
по ASN и отправляет GET к 1–5 точным URL внутри туннеля. Не выполняет POST,
HTTP-редиректы, обращения к Globalping или изменение правил GeoSite.
Для GET используется зафиксированный IPv4 адрес сайта, исходный hostname
остаётся в SNI и Host. Сопоставление удостоверяющей цепочки не отключается.

Первый прогон запрашивает один российский выход, до шести попыток
подключения и пять URL из `vpn-pilot/first-get.tsv`. Фактический выход
проверяется после установки VPN, конфликт ASN не засчитывается. При
запросе нескольких ASN один и тот же ASN с несколькими IP не считается
несколькими сетями. Успешное подключение само по себе не означает
доступность целей. Для успешного пилота нужна хотя бы одна HTTPS-реакция
с проверенным TLS на каждую из требуемых сетей, а также учёт всех целей
на этой сети. Для повтора из независимой сети укажите, например,
`--exclude-asn 34533`. Исключённые и повторные ASN пропускаются до
уменьшения лимита выходов и до любого GET к целям. Пропуски видны
в поле `skipped_asn_attempts` итогового JSON.

[Workflow GeoSite](../../../../../.github/workflows/geosite-vpnobratno-pilot.yml)
запускается только при изменении собственного YAML в исследовательской
ветке. Он не запускается при обычном push журнала или release-ветки.
После прогона смотрите `geosite-vpnobratno-summary.json` и
`vpnobratno-observations.jsonl`. Назначение свидетелей VPNObratno
отличается от точек Globalping, поэтому данные не меняют основной
счётчик охвата автоматически.

Для Linux с OpenVPN и правами сетевой изоляции можно вызвать тот же
адаптер с файлами и inventory, подготовленными как в workflow:

```sh
sudo bash "$UPSTREAM/vpn_netns_exec.sh" -- \
  timeout --signal=TERM --kill-after=6s 7m \
  python3 -B vpnobratno_get.py vpn-pilot/first-get.tsv \
    "$INVENTORY" "$UPSTREAM" "$NEW_REPORT_DIR" --exits 1 --attempts 6
```

Выходу нельзя приписывать статус домашней линии только по стране или ASN.
Перед публикацией сырых отчётов проверьте сведения об IP и публичных
ссылках. В журнал записывается итог, не содержимое VPN-профилей.
