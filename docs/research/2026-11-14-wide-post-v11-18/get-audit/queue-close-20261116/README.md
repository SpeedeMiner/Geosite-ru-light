Основание для Smart Cargo — опубликованная памятка о цифровом паспорте перевозки на самом рабочем хосте. Из AS12389 и AS57835 получены завершённые HTTPS 200 со строгим TLS, один и тот же PDF на 609 777 байт (валидные заголовок PDF и конец файла, SHA-256 `5e3d25d94ebabf54be37eca134686e114b2f7bbdd5bcf1dd49b2548e7d788a9f`). Публичная страница трекинга из тех же сетей вернула совпадающую SPA-оболочку. Оба опубликованных ресурса трекинга также полностью скачались и совпали побайтно в обеих сетях: CSS 676 857 байт и JS 2 622 166 байт. Авторизация, ввод номера груза, операции и IPv6 не проверялись.

У остальных пяти отложенных адресов последней логистической выборки решение — не включать в этот снимок. В частности, на `apicom.documentolog.com` последний запрос из AS12389 получил заголовки HTTP 200 со строгим TLS, но не закончил загрузку. В AS56420 DNS в этом проходе не подтвердился. Предыдущие 206 и полный GET вне российских выходов сохраняются как наблюдения и не означают недоступность хоста. Отложенные адреса прежних проходов не включались автоматически. Общий прогон завершился со статусом failure из-за Documentolog; обе группы Smart Cargo прошли.
