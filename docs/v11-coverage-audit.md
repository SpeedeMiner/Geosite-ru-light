## Механизм расширения и критерии безопасности

- Напрямую обходится дерево `include:` корня `category-ru` и дополнительные подтверждённые категории v2fly.
- Не преобразуются `full:`, `regexp:`, `keyword:` и строки с атрибутами в широкие suffix-правила.
- Корневые компактные TLD проходят стандартную дедупликацию и pruning.
- `tools/geosite-delta` декодирует оба protobuf DAT и сравнивает **семантическое покрытие** (включая предков RootDomain), а не простое количество строк.
- Потеря хотя бы одного RU правила, ранее покрываемого релизом, делает PR CI красным.
- Для PR отключены публикация GitHub Release и принудительный push в `release`.

## Не завершено / требуется перед merge

1. Подтвердить актуальное владение спорными техническими доменами, в том числе `ksn-crypto-info.com`.
2. Проверить, что шесть снятых блокировок соответствуют желаемой политике `geosite:block`.
3. Проверить новые сторонние кандидаты вне компактных корней по источнику, назначению, DNS и риску международного CDN **до** включения; массово не импортировать `external-candidates.json`.
4. После проверки перевести PR из Draft в Ready for review; `main`, `release`, теги и production не менять без отдельного решения.

## Дополнение — реестр решений по внешним кандидатам (12 ноября 2026)

Введён `data/v11-external-domain-review.tsv` — версиионируемый реестр решений `confirmed`, `hold`, `reject` с причиной. Сборщик DAT ничего не импортирует из этого реестра: он используется исключительно для контроля итогового покрытия.

Инструмент `tools/geosite-delta` при PR-сборке:
- требует сохранения RU-покрытия для всех строк `confirmed`;
- проваливает CI при появлении RU-покрытия для строк `reject`;
- оставляет `hold` на ручном рассмотрении без автоматического изменения маршрутов;
- публикует колонку `Review decision` и обоснование в `geosite_RU_external_candidate_audit.md`;
- сохраняет исходный TSV и отчёт внутри CI-артефакта.

Первые решения: `sbrf.com` — reject (доменная парковка); `avito.net`, `rutube.io`, `ozoncloud.com`, `2gis.io`, `gosuslugi.org`, `kinopoisk.net`, `hbrd.io` — hold (нет надёжного прямого подтверждения текущего использования); `importx5.com`, `vtbcapital.com`, `vigo.tech`, `samokat.tech`, `2gis.biz` — confirmed.

**CI:** https://github.com/SpeedeMiner/Geosite-ru-light/actions/runs/43256796697 — успешно; RU=3042, BLOCK=37, DAT=81894 Б; новых RU=23, потерь=0.

Внешний аудит: 926 записей в исходной очереди; 816 уже RU; 74 непокрытых с предупреждением; 36 непокрытых без предупреждения. Статусы решения по всему входу: confirmed=5, hold=7, reject=1, unreviewed=913. Эти группы считаются независимо от покрытия; например confirmed уже входят в RU. Число 36 — количество непокрытых без исходного предупреждения, оно включает некоторые hold/reject, и **не** равно числу полностью нерассмотренных доменов.

Дальнейшее улучшение: различать непокрытые решения hold/reject и реальные unreviewed в отдельном итоговом счётчике, чтобы не завышать ручную очередь.
