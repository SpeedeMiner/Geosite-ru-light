# v11 — источники доказательств принадлежности доменов

Дата исследования: 2026-11-12. Это каталог источников, **не** автоматический whitelist.
Для перечисления доменов российских компаний не использовать только географию IP или ASN CDN.

## Агрегаторы: поиск компания → домены

| Источник | Связи | Доступ и ограничения | Использование |
|---|---|---|---|
| [NetworksDB](https://networksdb.io/) | organization / networks / ASN / domain context | Бесплатный API: 1000 запросов/месяц с ключом, не все конечные точки доступны на всех тарифах. [API](https://networksdb.io/api/docs) | Поиск организаций и инфраструктуры, **кандидаты**, не автоматическая атрибуция |
| [Netlas](https://app.netlas.io/) | DNS, регистрационные и сертификатные записи, discovery graph | Бесплатно 50 запросов в день; Domain WHOIS и Certificate Search требуют более высокого тарифа. [API](https://docs.netlas.io/api-reference/), [тарифы](https://netlas.io/pricing/) | Обнаружение связанных доменов, проверка истории |
| [CTScout](https://ctscout.dev/) | OV/EV certificate organization → apex domains | Не охватывает DV-сертификаты; доступность API уточнять по документации сервиса | Более сильный сигнал юридического владельца, с проверкой сертификата |
| [DomainTools](https://docs.domaintools.com/api/lookups/reverse-whois/) | registrant name/email → domains, исторический WHOIS | Обычно платный | Проверка общего регистранта и предыдущих регистраций |
| [SecurityTrails](https://docs.securitytrails.com/docs/overview) | DNS, historical WHOIS, company data | API с ключом | Исследование доменов при неоднозначной принадлежности |
| [OpenCorporates](https://api.opencorporates.com/) | юридическое лицо, аффилированные названия | Ключ / условия использования | Нормализация названия компании; сам по себе не каталог её доменов |
| [urlscan.io](https://docs.urlscan.io/apis/urlscan-openapi/search) | веб-сканы, запросы к третьим доменам, TLS | Ограничения API, контекст может быть сторонним | Поиск потенциальных зависимостей **сервиса**, но не владельца |
| [ICANN RDAP](https://www.icann.org/rdap/) | регистрационные данные | Бесплатно; данные registrant часто редактированы | Проверка владельца только при открытой записи |
| [crt.sh](https://crt.sh/) | Certificate Transparency SAN / CT | Публичный поиск; одно SAN не гарантирует владение компанией | Выявление кандидатов по сертификатам, проверка issuer/type |

## Иерархия доказательств

**Strong / допустимо для предложения DIRECT:**
- Официальный сайт компании или её опубликованная документация прямо называет домен как собственный/сервисный;
- публичный RDAP регистранта с проверяемым юридическим названием (с учётом affiliate и изменений владения);
- сертификат OV/EV с проверяемым именем компании **вместе** с подтверждением, что домен сейчас используется в нужной системе.

**Corroborating / недостаточно по отдельности:**
- совпадение ASN или IP, особенно облаков и CDNs;
- одинаковые NS, MX, SOA или IP reverse DNS;
- DV-сертификат и его SAN, общие веб-трекеры и ссылки с сайта;
- название бренда внутри hostname, старый WHOIS, сведения из стороннего whitelist.

**Reject / hold:**
- регистрант или контент свидетельствуют о продаже/парковке;
- внешняя компания или международный сервис по похожему названию;
- принадлежность и цель службы не подтверждены;
- нет уверенности, подходит ли `domain:` (включает поддомены) или только `full:`.

## Проверочный конвейер v11

1. Собрать кандидатов по организации из NetworksDB и Netlas, затем из OV/EV CTScout и корпоративных страниц. Вести оригинальный URL и дату.
2. Перед добавлением сравнить с **текущим DAT** (корневые зоны, RootDomain, Full) — не добавлять избыточное.
3. Проверить текущий ownership и *service use*, а также не исключить ли домен из-за парковки/иностранного назначения.
4. При подтверждении внести только минимальное правило в `local/ru.txt`: `full:` для конкретного endpoint стороннего провайдера; `domain:` только если разрешено всё поддерево.
5. Добавить решение и ссылки в `data/v11-external-domain-review.tsv`; status `hold`/ `reject` не создают DIRECT.
6. Запустить PR CI, требовать `RU lost=0`, контроль `reject` и стабильное покрытие `confirmed`. Документировать изменение в `docs/v11-coverage-audit.md`.

## Разграничение автоматизации

**Без API-ключей** можно использовать текущий v2fly, официальные открытые источники, бесплатные страницы RDAP/CT и консервативный отчёт о кандидатах. Это не полный реестр доменов компаний.

Подключение NetworksDB/Netlas/DomainTools/CTScout в CI требует оценки доступных квот, ключей и лицензий. Не размещать ключи в репозитории; GitHub Actions secrets. Нельзя автоматически назначать `confirmed` по совпадению IP, ASN, имени или DNS. Любое внешнее дополнение сначала должно появиться в аудите, а затем пройти ручное утверждение.
