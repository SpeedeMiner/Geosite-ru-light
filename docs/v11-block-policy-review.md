## Принятое решение

1. **Не менять BLOCK в PR расширения RU.** Исходное содержимое `local/block.txt` взято из неизменённого `main` (`8a0ece73`); восстановлены все шесть записей, без добавлений и без удаления других правил.
2. `tools/geosite-delta` сравнивает весь опубликованный DAT и текущий кандидат не только по RU, но и по BLOCK: **любое новое или потерянное эффективное покрытие BLOCK проваливает CI**. Это не позволяет случайно изменить пользовательские блокировки при импорте сторонних списков.
3. Наличие пересечений `geosite:RU` и `geosite:BLOCK` **не доказывает** конкретный маршрут: итог зависит от порядка правил в конфигурации Xray/sing-box/клиента. В данном PR порядок не меняется.
4. Если потребуется исключить отдельные сервисные домены Яндекса/Mindbox из BLOCK, это должно быть отдельным изменением с явным решением об ожидаемом поведении. Документация выше указывает на возможный функциональный риск, но не является разрешением менять политику автоматически.

## Отдельное пользовательское правило 4PDA

`4pda.to` и `www.4pda.to` отмечены как `reject` в `data/v11-external-domain-review.tsv` по прямому указанию пользователя. CI независимо от наличия записей в инвентаре требует наличие обоих `reject` и запрещает в RU **весь суффикс `4pda.to`**, включая точные поддомены. Это **не включает** 4PDA в BLOCK.

Для общих глобальных CDN, например `akamaized.net`, отвергается только указанный корень: отдельный подтверждённый endpoint российского сервиса внутри общей зоны CDN может быть полезен для RU и не должен отсекаться автоматически. Поведение покрыто тестами `tools/geosite-delta/main_test.go`.

## Проверка перед слиянием

- `DELTA RU`: не допускаются потерянные правила.
- `DELTA BLOCK`: требуются **newly_covered=0** и **lost=0**.
- `4pda.to`: не покрыт ни RootDomain предком, ни Full/Root поддоменами.
- Очередь внешних доменов может иметь 0 unreviewed; `hold` — это решение о не-включении, а не доказательство принадлежности.
- PR остаётся Draft, `main`, `release`, теги и production не изменяются.
